# 比分、总进球与胜平负分析流程

## 可运行的实验模型

```sh
PYTHONPATH=src python -m sports_lottery.forecast data/processed/top5_2016_2026
PYTHONPATH=src python -m sports_lottery.forecast data/processed/top5_2016_2026 --league 'Premier League' --home Arsenal --away Chelsea --before 2026-07-01
```

第二条仅演示历史截止日期预测，并不表示该日存在此对阵。球队名须与输入数据完全匹配。

- 联赛基线：预测日前最近500场；至少100场。
- 球队状态：主队最近20场主场，客队最近20场客场；180天半衰期。
- 小样本向联赛均值收缩，相当于5场先验；参数预先固定，未针对测试结果优化。
- 输出模型期望进球（不是射门质量统计xG）、90分钟胜平负、前5个比分、总进球0至6与7+。
- 独立泊松假设未建模红牌、领先后的战术变化及双方进球相关性。
- 比分排序第一不代表高命中率。概率尚未校准，不显示“稳胆”“保证命中”。

## 回测规则

默认从2024-07-01开始评估，之前赛果用于初始化，每日预测后才加入当日赛果。
报告胜平负命中率、三分类Brier、对数损失、单一比分与单一总进球档命中率。
与同一历史窗口的联赛频率基准及始终主胜对比。
本次为回顾性评估，不是从未观察过的前瞻测试；未来需另存冻结预测检验。
未收集实际可售项目和出票固定奖金，不算收益率，不自动生成投注金额或下单。

## 每次真实比赛分析必须补核

1. 官方比赛编号、主客顺序、北京时间、赛事阶段、可售项目、停售和延期信息。
2. 首发与伤停：姓名、状态、来源网址、消息时间、核实时间。未知不能当作健康。
3. 近5/10场、主客表现、对手强度、休息天数、旅行及连续客场。
4. 杯赛首回合比分、晋级规则、排名目标；将有证据的事实和战意推测分开。
5. 数据来源互相矛盾时暂停明确推荐。伤停、战意不得只凭球队名气推断。
6. 赔率仅辅助比较：使用赛前时间戳，禁止拿赛后或临场不可获得赔率做回测。

上述实时因素尚未自动接入模型；只能作为明确标注来源的人工核对层。
官方接口受访问限制时停止，使用获准导出或授权服务，不绕过限制。

## 赛前记录字段

建议逐场JSON记录：match_id、kickoff、created_at、source_urls、source_observed_at、
model_version、input_snapshot_hash、market、selection、probabilities、warnings、
offered_odds、odds_timestamp、settlement_rule、actual_result。
赛后结果单独追加，不修改赛前预测；缺失字段用null，不补编造数值。
当前仅定义记录合同，自动快照与结算流水尚待实现。
